# Shalti HaZaken — in-shop catalog (PWA)

Touch catalog for the shop screen (brands → products → product page) plus an admin interface for
managing brands, products and categories, with an AI "fill from the web" helper.

Hebrew (RTL) by default with an English toggle. Installable, works offline on the shop device once loaded.

## How it's hosted (all free tiers)

```
 shop tablet / phone ──┐
 admin (any browser) ──┼──► static PWA (GitHub Pages) ──► Supabase: Postgres + Storage + Auth
 Dar's laptop ─────────┘        └─ AI buttons ──► local helper (npm run helper → claude -p)
```

- **Supabase** holds data, images and the two logins. Row-level security means nothing is readable without
  logging in. Free-tier projects pause after ~7 days with no traffic; a shop screen that's used daily keeps it awake.
- **GitHub Pages** serves the built app over HTTPS (needed for install + offline). Any static host works
  (Cloudflare Pages, Netlify, Vercel): build with `npm run build` and upload `dist/`.
- **AI helper** runs only on a laptop with Claude Code logged in. Without it the admin works fully, just
  without the ✨ AI buttons and "paste image URL".

## Logins

| Who | Where | How |
| --- | --- | --- |
| Shop screen / client | `<site>/` | shop code (digits), or open `<site>/?key=<shop code>` once — the device stays logged in |
| Admin | `<site>/admin` | admin password |

Both are generated by `npm run setup:supabase` into `credentials.local.txt` (git-ignored). Re-running the
script keeps them; delete that file and re-run to rotate both.

## First-time setup

1. Create a free project at supabase.com. From *Project Settings → API* copy the URL, `anon` key and
   `service_role` key into `.env.local`:
   ```
   SUPABASE_URL=https://xxxx.supabase.co
   SUPABASE_ANON_KEY=...
   SUPABASE_SERVICE_ROLE_KEY=...
   ```
2. Create the tables: paste `supabase/migrations/*_schema.sql` into the *SQL editor* and run it.
3. `npm install && npm run setup:supabase` — creates the logins, writes `web/.env.local`, and uploads
   the current catalog (`data/db.json` + `data/uploads/`). Use `--skip-data` to only (re)create logins.
4. Hosting: push to a GitHub repo, then *Settings → Pages → Source: GitHub Actions*, and add repository
   **variables** `SUPABASE_URL` and `SUPABASE_ANON_KEY`. The workflow in `.github/workflows/deploy.yml`
   publishes on every push to `main`. (Free GitHub accounts need the repo to be public for Pages; the
   anon key is designed to be public — RLS protects the data.)
5. On the laptop: `ALLOWED_ORIGINS=https://<user>.github.io npm run helper` to enable the AI tools in the hosted admin.

## Local development

```bash
npm run dev     # Vite on :5173 + AI helper on :8840, using the Supabase project in web/.env.local
```

A full local Supabase (Docker) also works: `npx supabase start`, then point `.env.local` at it.

## Data model

- Tables `categories`, `brands`, `products` store each item as a JSON document (`data`) plus `sort`.
  `product_prices` is separate so shop screens only receive prices while *Show prices* is on.
- `shared/specs.json` — spec fields per category template, flavour families, labels. Add a template there
  to support new product types (e.g. vaporizers), then create a category that uses it.
- `data/db.json` + `scripts/seed.js` — the original local data / website import, kept for the migration.
